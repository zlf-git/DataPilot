# DataPilot 五道闸门（F-04 安全兜底）

| 项 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 更新日期 | 2026-10-20 |
| 作者 | 张灵枫 |
| 关联文档 | IR_Schema.md（F-02）、Prompt模板.md（F-03） |

> 五道闸门是「LLM 生成 SQL」这条路径的硬兜底：Prompt 只能软约束 LLM，闸门在 IR 层、SQL 层、结果层三级拦截，保证即使 LLM 出现幻觉也不会造成越权、注入、拖垮集群。执行顺序如下。

## 执行链路与闸门位置

```
自然语言 → 召回 → Prompt → LLM 生成 IR
   → [闸门1 存在性] → [闸门2 权限] → [闸门3 代价]
   → IR 转 SQL → [闸门4 语法]
   → 执行(只读账号) → [闸门5 结果自检] → 返回
```

---

## 闸门 1：存在性闸门（IR 层，最先）

**职责**：确保 IR 中每个表、字段、指标都真实存在于 Ontology 白名单，把 LLM 幻觉率压到 0。

| 项 | 内容 |
|---|---|
| 校验对象 | IR 的 `table` / `field` / `metricId` |
| 校验规则 | 表 ∈ 4 张 ADS 表白名单；字段 ∈ 字段白名单；指标 ∈ `metric_def` 白名单 |
| 实现 | 白名单加载进 `HashSet`，O(1) 查找；字段按 `table.field` 复合键校验 |
| 违例处理 | 拒绝执行，返回「问题超出可查询范围」 |

**拦截示例**：LLM 幻觉生成字段 `total_sales`、表 `dwd_trade_order_detail`（文档假设表，真实环境不存在）→ 直接拦截，不会带到 SQL 层。

---

## 闸门 2：权限闸门（IR 层）

**职责**：只允许读，且只允许读白名单内的表；执行账号本身也只读，双保险。

| 项 | 内容 |
|---|---|
| 校验对象 | IR 涉及的表 + 执行账号 |
| 校验规则 | 表 ∈ 只读表白名单（4 张 ADS）；执行账号无写权限 |
| 实现 | 执行固定用 StarRocks 只读账号 `agent_ro`（仅 SELECT 授权）；IR 本身不含写语义 |
| 违例处理 | 越权表拒绝；写操作在账号层直接报权限错误 |

**双保险**：① IR 层校验表白名单；② 账号层 `agent_ro` 连 UPDATE/INSERT/DELETE 权限都没有，即便某层漏过，写入也会被数据库拒绝。

---

## 闸门 3：代价闸门（IR 层）

**职责**：预估查询复杂度，防止 LLM 生成全表扫描、多表笛卡尔积等拖垮集群的查询。

| 项 | 内容 |
|---|---|
| 校验对象 | IR 的指标数、维度数、join 表数、limit |
| 校验规则 | `复杂度 = 指标数 × 维度数 × join表数`；硬性上限：join 表数 ≤ 2、指标数 ≤ 3、limit ≤ 1000 |
| 实现 | 从 IR 直接计算，无成本即可预估 |
| 违例处理 | 超阈值拒绝，返回「查询过于复杂，请拆分问题」 |

**拦截示例**：LLM 想把 4 张表全 join 起来（join 表数 = 4 > 2）→ 拦截。单机 demo 数据量小，阈值给得宽松，但机制是生产可用的。

---

## 闸门 4：语法闸门（SQL 层）

**职责**：IR 转成 SQL 后，用 JSqlParser 解析校验语法合法性，并二次比对表/字段白名单（防 IR→SQL 转换引入非法引用）。

| 项 | 内容 |
|---|---|
| 校验对象 | 由 IR 生成的 SQL 字符串 |
| 校验规则 | `CCJSqlParserUtil.parse(sql)` 解析通过；解析出的表名/字段名 ⊆ 白名单 |
| 实现 | JSqlParser 提取 `TablesNamesFinder` 表名 + `Column` 字段名，与白名单比对 |
| 违例处理 | 解析失败或引用越权 → 拒绝执行 |

**双重价值**：① 语法合法性；② 即使 IR 层漏过，SQL 层的表/字段提取再次兜底，幻觉归零有第二道防线。

---

## 闸门 5：结果自检（结果层）

**职责**：对执行结果做合理性自检，把「无数据 / 异常值 / 超长结果」包装成可读反馈。

| 项 | 内容 |
|---|---|
| 校验对象 | SQL 执行结果集 |
| 校验规则 | 空结果 → 提示无数据；行数超阈值 → 截断；数值异常（如负 GMV、NULL 指标）→ 标记告警 |
| 实现 | 结果集元信息 + 抽样校验；告警信息随结果返回 |
| 违例处理 | 不拦截，但附告警说明，帮助用户判断结果可信度 |

**示例**：查「某渠道某天 GMV」，结果为空 → 返回「2026-10-19 小程序渠道无数据」，而不是把空表直接抛给用户。

---

## 五道闸门总览

| 闸门 | 层 | 拦截什么 | 关键手段 |
|---|---|---|---|
| ① 存在性 | IR | 幻觉字段/表/指标 | Ontology 白名单 Set 查找 |
| ② 权限 | IR + 账号 | 越权/写操作 | 只读表 + `agent_ro` 只读账号 |
| ③ 代价 | IR | 大查询/笛卡尔积 | 复杂度公式 + 硬上限 |
| ④ 语法 | SQL | 语法错误 + 二次越权 | JSqlParser 解析 + 提取比对 |
| ⑤ 结果自检 | 结果 | 无数据/异常值 | 结果集元信息校验 |

**面试可讲的核心论点**：Text2SQL 的最大风险不是「SQL 写得慢」，而是「LLM 幻觉导致查错表、造字段、甚至拖垮集群」。五道闸门把生成空间收敛到白名单内，幻觉在 IR 层就被拦截，SQL 层再兜底一次，账号层只读三重保险——这是「语义层约束生成空间」技术路径区别于「裸调 LLM 生成 SQL」的关键。
