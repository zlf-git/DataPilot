**与票面的偏差（1 条，已定性）**
- 票面「五道闸各 1 个 reject 用例」第 5 条无法成立：`GateResult` 契约明确「结果自检通过但可疑时返回 ok + warning（不拒绝，只附加告警）」——空结果不是错误。因此闸门⑤的用例改为断言**不 reject + warning 能穿过 GateChain 到调用方**，这恰好是 QA-05 P2-1 的回归点（此前 `runPhase` 一律 `return ok()`，warning 永远到不了 AgentEngine）。另补「单行全 null 也算无数据」一例。

**QA-05 三项「测不出来」的收口结论（本票实测，含一条纠正）**
- **U1 分母为 0 的 NULLIF**：单测只能锁 SQL 形状（`ROUND(分子 / NULLIF(分母, 0), 4)`）。值级实测在 StarRocks 3.3.8 上补做：`SELECT ROUND(1 / NULLIF(0,0), 4)` → `NULL`，且 `SELECT 1/0 IS NULL` → `1`。**即 StarRocks 除零本来就返回 NULL、不抛异常**，`NULLIF` 的价值是「语义显式 + 跨引擎可移植」，不是「防崩溃」——QA-05 U1 里「分母为 0 会打断链路」的隐含假设不成立，已按实测纠正。
- **U2 参数顺序错位**：本设计下跨表占比只继承时间条件，两组参数值恒相同（`[from, anchor, from, anchor]`），**把两组整体互换不可观测**；但「from 与 anchor 写反」可观测。故单测断言完整参数列表 + 两处 `WHERE dt > ? AND dt <= ?` 计数，把能锁的部分全锁住。
- **U3 分母表 anchor 错位**：`verify(anchorProvider, times(1)).anchor(...)` 证明锚点只取一次、分母复用主表条件，不存在第二套 anchor。残留风险转为数据侧：若分母表在该窗口无数据，分母子查询返回 NULL → 占比整体 NULL。归 Ticket 16 值域告警 + `ResultCheckGate` 处理，不在本票。
