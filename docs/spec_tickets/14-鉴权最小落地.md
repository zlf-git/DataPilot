# Ticket 14：鉴权最小落地

## 目标
Spring Security 三角色，`/api/gate-config` 与 `/api/metrics` 的写操作仅管理员，且放行 `/api/ask` 避免集成测试 401。

## 背景
来自 D7（Spec §3 阶段④）。审计 P1#8：鉴权是后端能力，跟前端无关；且 14 一上线 Spring Security 默认拦所有 /api/**，会导致 01/06 集成测试和 eval 脚本全 401。
审计 P0#2（复审）：`PUT /api/metrics` 能改 `metric_sql`，是绕过五闸的注入面，必须与 gate-config 同级保护。

## 修改范围
- config：SecurityConfig
- controller：gate-config / metrics 写操作鉴权

## 任务
1. Spring Security 三角色（业务/管理员/DBA）
2. **写操作仅管理员：`PUT /api/gate-config` 与 `PUT /api/metrics`**（metric_sql 是注入面，不能只保护 gate-config）
3. **放行 `/api/ask`、`/api/traces`（或 eval 脚本带头），避免 01/06 集成测试全 401**
4. 测试用 @WithMockUser 标注角色

## 验收标准
未授权 PUT `/api/gate-config`、`PUT /api/metrics` 均返回 401/403；`/api/ask` 仍可匿名访问跑通。

## 测试要求
集成测试：未授权/业务角色 PUT gate-config 与 metrics → 401/403；管理员 PUT → 200；/api/ask 匿名 → 200。只测外部行为。

## 依赖
Ticket 02 + Ticket 01b

## 预估
0.5 天

## 不包含
- 完整 RBAC/多租户（Spec §6 分期做）
- 前端登录 UI（Ticket 13 范围外）

## 落地记录（2026-10-21）

**结论：三个角色 + HTTP Basic 落地，只保护写接口；未授权 PUT 返回 401、角色不够返回 403、`/api/ask` 匿名照常 200。**
验收不是「配了 Security 就算」，而是 `SecurityAccessTest`（15 例，只断言 HTTP 外部行为）+ 真实浏览器冒烟（32/32）+ 端到端跨身份执行拒绝（`verify_hitl` 76/76）。

### 1. 角色边界（票面只说「三角色」，边界是这里定的）

| 角色 | 能写 | 不能写 | 理由 |
|---|---|---|---|
| `BUSINESS` 业务 | — | 全部 | 业务方只问数、看结果；口径与阈值不是他定的 |
| `ADMIN` 管理员 | 指标口径、闸门阈值、字段白名单 | — | 票面「写操作仅管理员」；`metric_sql` 是注入面（审计 P0#2），必须与 gate-config 同级 |
| `DBA` | 仅字段白名单 | 指标、闸门 | 白名单是「库里有哪些列」的事实，归 DBA；但他不该能改业务口径或给自己放宽闸门 —— **DBA 是 admin 的子集，不是别名** |

读到的东西全部匿名开放：`GET /api/metrics|gate-config|metadata/**`、`POST /api/ask|preview|execute`、`GET /api/traces`、`GET /api/health/*`。
理由写在 `SecurityConfig` 的类注释里：读走只读账号 + 五道闸门，最坏是「查到一个数」；写能改口径和阈值，等于改「什么 SQL 算合法」，必须有身份。

### 3. 三条踩出来的坑（都写进代码注释了）

1. **`@AuthenticationPrincipal(expression = "username")` 在匿名请求上直接 500。**
   匿名时 principal 是个 **String**（`"anonymousUser"`），在 String 上取 `username` 属性抛异常 ——
   表现是「预览接口 500」，而当时我以为是鉴权配错了。改成注入 `Authentication` + `instanceof AnonymousAuthenticationToken`。
2. **401 带 `WWW-Authenticate` 会让 headless Chrome 的 fetch 永远不返回。**
   冒烟脚本报 `Runtime.callFunctionOn timed out`。真实浏览器里则是盖一个与页面无关的原生登录框 ——
   而本项目的设计恰恰是「没有登录页，凭证由页面输入框设置」。所以**不加这个头**，只留 JSON 原因。
   这是「按规范加头」与「按设计不加头」的冲突，选了后者，理由写在 `SecurityConfig.unauthorized()` 的注释里。
3. **`AnonymousAuthenticationToken.getName()` 是 `"anonymousUser"`（大写 U）。**
   如果直接拿 `getName()` 当 owner，匿名预览存 `anonymousUser`、而常量是 `anonymous`，
   「匿名预览 + 匿名执行」会被判成两个身份 —— HITL 整体不可用。所以显式判匿名 token 再归一。

### 5. QA-12 P2-3 收口：previewId 现在有归属

票面没写，但上一轮评审把它挂在 Ticket 14 名下，一并做了。

- `PreviewStore.Preview` 加 `owner`；`save(ctx, owner)`；`ownedBy(current)` 比对。
- `HitlController` 从 `Authentication` 取名，匿名归一成 `anonymous`。
- `AgentEngine.executePreview(..., owner)` **在开 trace 之前**判身份：不匹配 → REJECTED、不发 SQL、`log.warn` 留痕（只进应用日志，不落 `agent_run` —— 它没跑任何东西，记一条会让成功率统计失真）。
- 端到端实测（`verify_hitl` ⑨c）：
  - 匿名执行 admin 的预览 → `REJECTED`，文案「这份预览不是你生成的（预览时身份：admin，当前身份：anonymous）」，`rows=[]`、`sql=null`；
  - 同一个 previewId 由 admin 执行 → `SUCCESS` 且 `gmv_channel=15604.97`（**快照没被越权请求烧掉**）；
  - 反方向：admin 执行匿名预览 → 同样 REJECTED。

### 6. 票面偏差（4 条）

1. **DBA 的权限票面没写**，只列了「三角色」+「写操作仅管理员」。定了「DBA = 白名单」，并在表里写明 DBA 是 admin 的子集而不是别名；
   `PUT /api/metadata/**` 归 ADMIN+DBA（这条接口本身是 Ticket 13 加的，票面写的时候还没有）。
2. **`write-enabled` 默认值从 `false` 改成 `true`，语义从「安全兜底」变成「运维急停」。**
   票面的隐含假设是「Ticket 14 之前用开关兜底，Ticket 14 之后用鉴权」；如果开关保持默认关，管理员也写不进去，
   Ticket 13 的「白名单有维护入口」当场失效。所以改默认值，并在 `MetadataController` 类注释里写明现在有**两层**：
   有身份 ≠ 允许写（急停态下 admin/dba 一样 403，`smoke` 与 `SecurityAccessTest` 各锁了一条）。
3. **票面「不包含前端登录 UI」→ 仍加了一个凭证输入框（不是登录页）。**
   不加就等于 Ticket 13 的白名单/指标/闸门三个页面在默认配置下全部只读 —— 那不是「少做一点」，是把上一票的验收打回原形。
   所以做的是最小的那个：页头一个按钮 + 弹窗两个输入框，存 `sessionStorage`，401 时自动弹出来。
   没有路由守卫、没有登录页、没有 token 刷新。
4. **鉴权默认开启，没有总开关。** 票面验收要求「未授权 PUT 返回 401/403」，那就不能有「关掉鉴权」的配置项 ——
   有的话它迟早会出现在生产配置里。要冻结写入用急停开关，那是有日志、有文案、不影响身份判断的另一件事。

### 7. 已知边界

- **凭证是 `sessionStorage` 里的 base64，不是加密。** 能读这个标签页的人就能拿到凭证。真实系统要走服务端会话或短期 token，属 Spec §6 分期。
- **用户表在内存里**（`InMemoryUserDetailsManager`），重启即恢复默认三个账号；密码用 BCrypt 在启动时 encode。
  不做用户管理、不做改密 —— 票面「不包含完整 RBAC/多租户」。
- **`/api/traces` 仍然匿名**：里面有 SQL 文本与结果行。票面要求放行（否则 01/06 集成测试与 eval 脚本全 401），
  所以本票不动；真实部署时这里应该至少要求 `BUSINESS` 以上。
- **401 不带 `WWW-Authenticate`**：不符合 HTTP 规范，但符合本项目「无登录页 + 显式 Authorization 头」的设计（原因见第 3 节第 2 条）。
