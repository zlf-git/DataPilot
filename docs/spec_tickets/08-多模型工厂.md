**关键实现决定**

1. **工厂不产 stub，是硬拒绝不是约定**：`LlmClientFactory.resolve()` 收到 `stub`/空值时抛
   「只产真实 provider，不产 stub」，而不是造一个桩返回。审计 P0#2 的真实风险不是「多一个便利入口」，
   而是「配了 deepseek 但 Key 没读到 → 静默退回桩 → 拿到一张看着正常的错数」。同理缺 Key 也直接抛，
   文案指明该设哪个环境变量。
2. **一个真实实现类 + 参数化，而不是每厂商一个类**：DeepSeek 与 Qwen 的差异只有 base-url、模型名、
   Key 环境变量三项，写在 `LlmProvider` 枚举里；将来接 Kimi / 智谱 / 本地 vLLM 只加一个枚举项。
   这也让「切 provider 只改一行」有地方落：`provider: qwen` 之后 base-url 与模型名自动跟着换。
3. **自定义 `@Conditional` 而不是 `@ConditionalOnProperty`**：后者只吃单值，两个 provider 就得写两个
   `@Bean` 方法（每加一个厂商再加一个）。「哪些值算真实 provider」本来该由 `LlmProvider` 一处定义。
   非法值在条件求值时就抛 —— 与 Ticket 07 的 `engine.type` 同款：**启动即失败**，不留
   「启动成功但容器里没有 `LlmClient` → 问到第一个问题才 NoSuchBeanDefinition」。
4. **base-url 归一化**：Spring AI 的 `OpenAiApi` 自己拼 `/v1/chat/completions`，用户按习惯写
   `.../compatible-mode/v1` 会拼出 `/v1/v1/...` 的 404，而这种错只有在真实调用时才暴露。工厂统一
   剥尾斜杠与结尾 `/v1`，**只剥结尾**（网关路径中间的 `v1` 不动）。实测传 `http://127.0.0.1:9/v1/`
   → 健康检查回报 `http://127.0.0.1:9`。
5. **`descriptor()` 有真实消费方**（吸取 QA-05 P2-3 `braces()` 死代码的教训）：`GET /api/health/llm`
   与启动日志都读它。它的价值在「环境变量没导、占位符没替换」这类静默失败：光看 yml 看不出到底连的谁，
   切完 provider 打一次接口就知道。
6. **Key 只走环境变量链**：`datapilot.llm.api-key` 留空 → 读 `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY`。
   显式配置优先于默认值，默认值优先于环境变量，三档顺序写在 `resolve()` 一处。
7. **`spring.ai.openai.*` 保留但不生效**：Spring AI 的 `OpenAiAutoConfiguration` 在 api-key 为空时
   会启动失败，保留带占位符的这段只是为了让自动配置能建 bean；真正决定端点的是 `datapilot.llm`。
   yml 注释里写明了，避免后来人改错地方。

**本轮踩到并修掉的缺陷（自引入，P1 级）**

- **现象**：`@EventListener(ApplicationReadyEvent.class) public void reportLlm(LlmClient client)` 让应用
  **启动完再崩**：`Started DataPilotApplication in 2.6s` 之后紧跟
  `IllegalStateException: argument type mismatch`，进程退出。
- **根因**：`@EventListener` 的单参数方法把第一个参数当**事件体**传，`LlmClient` 不是
  `ApplicationReadyEvent` 的 payload，反射调用时类型不匹配。写法上很像「顺手注入一个 bean」，实际不是。
- **修复**：改为无参方法 + 构造注入 `ObjectProvider<LlmClient>`（懒解析，也顺便避开本类同时产出
  `LlmClient` bean 的自引用）。已加 `LlmClientConfigTest.startupSelfCheckRunsWithoutCrash`
  手动 `publishEvent(new ApplicationReadyEvent(...))` 钉死 —— 单跑 `mvn test` 时 `ApplicationContextRunner`
  不触发 ready 事件，这条用例是被真实启动咬出来之后补的，也做了变异验证（改回带参签名 → 用例红）。

**与票面的偏差（1 条）**

1. 票面任务 1 写「LlmClient 工厂按 provider 创建」。实现上工厂**不是**「每个 provider 产一个类」，而是
