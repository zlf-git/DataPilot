### 闸门各分支的触发证据（含 PUT 热更）

| 分支 | 用例 | 结果 |
|---|---|---|
| 代价·指标数 | 4 指标 IR | `代价=REJECT`：`指标数 4 > 3` |
| 代价·limit | `limit=5000` | `代价=REJECT`：`limit 5000 超过上限 1000` |
| 代价·join | `max_join` PUT 成 1 后，3 指标跨 3 表 | `代价=REJECT`：`join 表数 2 > 1`；恢复 2 后回到 PASS |
| 语法·字段二次兜底 | PUT 指标 `metric_sql=SUM(ghost_col)` | IR 层三闸门 PASS，`语法=REJECT`：`SQL 引用了白名单外的字段：ghost_col` |
| 结果自检·warning 通路 | 空结果 | 见 DoD#9，warning 未产生 |

**代价闸门的 join 分支有个前提**：默认 `max_join=2` 且只有 4 张表时，3 个指标最多跨 3 表 → `join=2`，不满足 `>2`；4 个指标会先被指标数上限拦掉。也就是说**默认阈值下 join 分支不可达**，必须调 `max_join` 才会触发（我这轮就是把它 PUT 成 1 才验证到的）。

## 3. 缺陷清单

### P1-1 结果自检的「空结果」分支在当前链路下不可达，DoD#9 实测不成立

`SELECT SUM(total_gmv) … WHERE dt='1999-01-01'` 不返回 0 行，而是返回 **1 行 `{gmv_total: null}`**（聚合函数对空集的行为）。`ResultCheckGate` 只判 `rows==null || rows.isEmpty()`，因此：

- `结果自检=PASS`（其实是没检查到）
- `answer=''`，前端会拿一个 null 当答案展示

后果：最需要包装的场景（查了个不存在的日期/条件）恰恰不触发；用户看到空白而不是「无数据」。

### P1-2 语法闸门的字段比对没有表作用域，跨表字段幻觉能穿过全部五道闸门

实测：PUT 一条指标 `metricId=qa_qatest_badsql, metric_sql=SUM(gmv), table_name=ads_trade_overview_di`（`gmv` 是渠道表的字段，trade 表没有），然后按该指标提问：

```
gates : ['存在性=PASS','权限=PASS','代价=PASS','语法=PASS']
sql   : SELECT SUM(gmv) AS qa_qatest_badsql FROM ads_trade_overview_di WHERE dt = ?
answer: 'SQL 执行失败：BadSqlGrammarException … Unknown column gmv'
```

`SqlValidator` 比对的是 `cache.fields()`（**全局去重字段名集合**），不是 `table.field`。同时 `OntologyCache.tableFields()` 已经建好 `table.field` 集合却**全仓无人调用**——说明本意是做表级作用域，实现时漏了。

后果：幻觉在字段级仍然存在（只是被 DB 报错兜住，不会注入、不会返回错数），「字段幻觉归零」这句结论要打折。修起来很便宜：`SqlValidator` 已经能拿到 SQL 里的表名，把列名和表名拼成 `table.field` 去比 `tableFields()` 即可。

### P1-3 权限闸门没有独立拦截能力

`AuthorityGate` 的全部逻辑是：IR 里每个 metric → 查 `metricTables` → 判 `tables().contains(table)`。这和 `ExistenceGate` 那段表校验**完全重复**；而 `ExistenceGate` 已经先执行，所以权限闸门永远拦不到任何东西。

另外两点：
- IR 结构里没有 `table` 字段，用户/LLM 无法直接表达表名，所以「IR 涉及表 ⊆ 只读表白名单」这件事本身没有着力点；
- `metrics` 为空的明细模式（Q4/Q5 那类）下，权限闸门**零校验就 PASS**；
- ticket 里写的「语句类型为只读 SELECT」在 IR 阶段无从校验（IR 不是 SQL），真正的只读保证来自 `agent_ro` 账号。

结论：权限闸门当前是**占位实现**。要么在票面上写明「本票仅占位，等 IR 支持 table 字段后重做」，要么把它改成对 `dimension`/`filter` 涉及表的推导校验，否则测试会误以为这里有防护。

## 6. 修复建议（按优先级）

1. **补「聚合空集」判定**：`ResultCheckGate` 在 `rows.size()==1` 且所有指标列为 null 时返回 `okWarning("无数据：…")`；顺手把 `answer` 的取值改成「warning 优先、再 errorMessage」，避免空结果被展示成空白。
2. **语法闸门改 `table.field` 作用域比对**：`SqlValidator` 里取了表名后，对每个列名做 `表.列` 匹配 `tableFields()`（`tableFields()` 现在没人用，正好接上）；对多表/无表名限定的列退回全局字段集并加 warning。
3. **权限闸门定性**：要么票面上标「占位」，要么补上对 `filter.field`/`dimension.field` 所属表的推导校验；否则它和存在性闸门重复，测试和评审都会高估防护力。
4. **`GateChain` 回显带上 reason/warning**（如 `代价=REJECT(指标数 4>3)`），warning 列表单独收集，避免多闸门 warning 互相覆盖。
5. `SqlValidator` 补 `SetOperationList`（UNION）与子查询的列提取。
6. `limit` 缺省时在 converter 补默认 `LIMIT`，把「无上限全表聚合」从结果层截断提前到 SQL 层（可与 Ticket 15 合并）。
