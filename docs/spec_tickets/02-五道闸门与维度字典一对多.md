# Ticket 02：五道闸门 + 维度字典一对多

## 目标
实现 Gate 接口 + 存在性/权限/代价/语法/结果自检五闸门 + GateChain，接入 AgentEngine；dimension_def 的 dt 改一对多。

## 背景
来自 F-04 五道闸门 + Spec §4.2 GateChain + §4.4 Gate 接口 + B6（Spec §3 阶段②）。安全兜底核心 + 修复 dt 维度越界误拦。

## 修改范围
- `agent/gate` 包：新增 Gate 接口 + 5 实现 + GateChain
- AgentEngine：接入 GateChain
- `sql`：SqlValidator 用 JSqlParser
- `seed.sql`：dimension_def 日期维度一对多

## 任务
1. Gate 接口 + GateChain 按序执行 fail 即停
2. 存在性闸门（白名单 **Caffeine 缓存，TTL 60s + 监听 Ticket 01b 的 MetadataChangedEvent 立即刷新**，O(1) 拦幻觉字段/表/指标；不要每次请求查库，也不要只在启动加载；**selectMode=DETAIL 时 metrics 可空、dimensions≥1，存在性闸门不把「无指标」当幻觉拦**——审计 P1#12，否则 Q4/Q5 纯 DISTINCT 题被误拦）
3. 权限闸门（**校验 IR 中所有表 ∈ 权限白名单、语句类型为只读 SELECT**；`agent_ro` 是 DB 侧第二道保险，不在本闸门内校验——应用层读不到 DB 账号权限）
4. 代价闸门（复杂度公式 + 硬上限，基础版）
5. 语法闸门（JSqlParser 解析 + 二次提取比对）
6. 结果自检（空结果/异常值包装）
7. dimension_def 的 dt 支持跨 4 表（一对多）

## 验收标准
幻觉字段/表/指标被存在性闸门拦截返回原因；恶意 SQL 不执行；Q1 正常通过；含 dt 过滤的题不因维度越界被误拦；**PUT 一条新指标后，不重启即可被闸门识别（≤60s 或事件触发）**。

## 测试要求
集成测试：① 含幻觉字段的 IR → 断言拦截且不执行；② 正常 IR → 断言通过；③ 空结果 → 断言包装「无数据」；④ dt 过滤不误拦；⑤ PUT 新指标后断言白名单已刷新。只测外部行为。
