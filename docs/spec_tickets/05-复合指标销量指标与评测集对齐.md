## 目标
composite 指标输出 `ROUND(a/b,4)` 两列；补 sale_cnt_product 与跨表占比 gmv_channel_ratio；评测集补 WHERE。

## 背景

- `docs/评测集.md`：补 WHERE

## 任务
1. seed 补 `sale_cnt_product = SUM(sale_cnt)`（Q8 销量指标，metric_type=simple，table=ads_product_sales_rank_di）
2. **seed 补跨表占比指标 `gmv_channel_ratio`（审计 P0#6，Q15 必须走指标命中）**：metric_sql=`SUM(gmv)`、metric_type=`composite`、table_name=`ads_channel_conversion_di`、denominator_table=`ads_trade_overview_di`、denominator_sql=`SUM(total_gmv)`
3. **seed 修 pay_conversion_rate 裸列名（审计 P1#15）**：`metric_sql` 由裸列名 `pay_conversion_rate` 改 `SUM(paid_order_cnt)/SUM(order_cnt)`，metric_type 由 simple 改 composite（裸列名过不了 01b 正则）
4. composite 分支：分子取当前表指标；分母若在另一张表，用标量子查询 `(SELECT SUM(total_gmv) FROM mall_dw.ads_trade_overview_di WHERE dt = ?)`（**分母必带 SUM，审计 P1#14**），不生成 JOIN——Q15 是 `渠道GMV（channel 表）/ 总GMV（trade 表）`，评测集标准 SQL 用 JOIN，生成器用标量子查询，二者结果等价，对拍只比结果不比 SQL 文本
5. **参数拼接顺序（审计 P1#14）**：分母标量子查询的 `dt = ?` 参数在前，主查询参数在后，统一由生成器按「分母子查询 → 主查询」顺序压参数
6. `metric_def` 加 `denominator_table` / `denominator_sql` 列（空 = 同表比值；填表名 = 跨表标量子查询）
7. 中间列在 SQL 内消掉，最终 `SELECT dim, ROUND(a/b,4) AS ratio` 恰好 2 列
8. 评测集 Q2/Q11-Q14 标准 SQL 补半开区间 WHERE
9. 更新 stub_ir：q8 走 sale_cnt_product 指标、q15 走 gmv_channel_ratio 复合指标

## 验收标准
Q8 走指标命中；Q15 返回恰好 2 列 ratio（3 行，按渠道）对拍通过且 **SQL 含分母表的标量子查询（带 SUM）**；评测集标准 SQL 与生成器结果一致（写法可不同）；pay_conversion_rate 不再是裸列名。
