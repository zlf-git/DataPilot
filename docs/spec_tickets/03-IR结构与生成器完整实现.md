# Ticket 03：IR 结构与生成器完整实现

## 目标
QueryIr 加 selectMode + OrderBy 引用 metricId，生成器实现 SELECT DISTINCT / ORDER BY 别名 / LIMIT 兜底 / 参数分派；Prompt 注入日期归一化规则；DETAIL 选表反查。

## 背景
来自 B1 selectMode + B4 别名排序 + D3 limit 兜底 + D4 参数分派（Spec §3 阶段②④、§4.3）。审计 P0#6、P1#12/#13：删 BETWEEN、补日期归一化、DETAIL 选表反查。

## 修改范围
- `ir` 包：QueryIr 扩展、FilterOp 枚举
- `sql/IrToSqlConverter`：生成器
- `Prompt模板.md`：selectMode + 日期归一化说明
- `src/main/resources/stub_ir/`：更新 q4/q5/q6/q11-q13（补 selectMode/别名排序字段）

## 任务
1. QueryIr 加 selectMode{AGG,DETAIL}，metrics 可空但 DETAIL 时 dimensions≥1
2. DETAIL 分支生成 SELECT DISTINCT
3. **DETAIL 选表反查（审计 P1#13）**：metrics 空时，从 `dimension_def` 的 field→table 反查确定目标表（例如 dimensions 含 `province_name` → 反查到 ads_region_gmv_di）；反查不到或多表冲突时报「无法确定目标表」
4. OrderBy 支持 metricId，生成 ORDER BY <alias>
5. limit 空时注入 gate_config.max_rows
6. **FilterOp 只留 EQ/IN/LIKE/GT/GE/LT/LE，删 BETWEEN**（BETWEEN 是闭区间，与 04 半开区间同源风险）
7. 参数分派：EQ 1个 / IN n个 / LIKE 包 `%` / GT/GE/LT/LE 各 1个
8. **日期归一化：Prompt 注入 today=2026-10-20 + 规则「未写年份取今年、未写日期取 MAX(dt)」，加对应 few-shot 1 条**（否则 Q1/Q3/Q6/Q7 的「10月19日」变不成年份）
9. 更新 stub_ir 对应题：q4/q5 补 selectMode=DETAIL，q6/q11-q13 补 ORDER BY 别名引用 metricId

## 验收标准
Q4/Q5 生成 SELECT DISTINCT；Q11-Q13 按聚合别名排序；无 limit 的 IR 生成带 LIMIT；三种 op 参数个数正确；「10月19日」归一化为 dt='2026-10-19'；DETAIL 无指标时从维度字典反查表成功。

## 测试要求
集成测试：StubLlmClient 打 Q4/Q5/Q6/Q11-Q13，断言 SQL 文本/执行结果对拍；断言 FilterOp 无 BETWEEN；断言日期归一化；断言 DETAIL 反查表。只测外部行为。
