### 4. 冒烟抓到的两条真 bug（页面自测发现、已修）

1. **`saveField` 丢 `field_role`**（Ticket 01b 遗留）。原有 SQL 的 `ON DUPLICATE KEY UPDATE` 只更新
   `field_type/field_comment/enum_values`，没有 `field_role` —— 白名单页把角色从 dimension 改成 metric 会
   「接口返回成功、库里没变」，是最难查的那种假成功。已把 `field_role` 加进 INSERT 与 UPDATE 两侧。
2. **`enum_values` 空串撞 JSON 列**。前端表单留空传的是 `""`，MySQL JSON 列直接报
   `Invalid JSON text: "The document is empty."` → 400 带一坨 `PreparedStatementCallback` 原文。
   修法在写入口归一化：空串/空白 → `null`（「留空 = 没有枚举」这条语义归写入口，不能让每个调用方各自记得传 null）。
   教训与 QA-08 同源：**空值 = 默认值，必须由装配/写入口决定，不能指望调用方。**

### 5. 票面偏差（6 条）

1. **「元数据页（可选）」→ 必需，而且它不是只读页**：票面任务 3 写「只读展示 + 字段白名单编辑」，
   但当时后端**只有 `GET /api/metadata/fields`**，没有表清单、更没有字段写接口 —— 照票面做只能画一个假的编辑框。
   因此本票补了三个接口（tables 读、fields 写/删）。这是本票唯一的后端改动，也是「白名单有维护入口」这条验收的前提。
2. **契约以实际实现为准，不以 `docs/前端.md` 为准**：文档里写的 `PUT /api/metrics/{id}`、`PUT /api/gate-config/{key}`
   在实现里是 `PUT /api/metrics`（body 带 metric_id）、`PUT /api/gate-config`（body 带 param_key）。
   页面按实现写，文档同步改了（见 `docs/前端.md` 第 5 节）。
3. **`gates` 是字符串数组不是对象数组**：文档示例是 `[{name,status}]`，实际是 `["存在性=PASS", ...]`。
   页面按 `name=verdict` 解析，并处理 `PASS(WARN)`。
4. **`chartType=null` 要显式处理**：Ticket 11 起失败响应 `chartType` 是 `null`（不再谎报 table），
   页面据此决定「没有结果」而不是渲染空图。
5. **HITL 进了问数页，没独立成页**：Ticket 12 给的 `previewId/edits/structuralChanges` 三个字段，
   只有在「先预览 → 改 → 执行」这条交互里才有意义，单独开页反而割裂。所以是两个按钮 + 一个抽屉。
6. **不做 AntV G2**（票面「不包含」已写明），报告图表走 `reportHtml` 自带的 ECharts，用 iframe 隔离；
   也**不做登录 UI**（Ticket 14 的范围），写接口靠 `write-enabled` 开关兜底，页面把开关状态显式展示。

### 6. 已知边界

- **前端不做任何裁决**：编辑合法性由服务端 diff 判定，页面只是「尽量不给越界的机会」（指标/时间窗口在抽屉里只读）。
  即使有人改前端，越界照样被 `IrEditGuard` 判 REPLAN —— 前端拦不拦不影响安全边界。
- **`dist/` 与 `node_modules/` 不入库**（`frontend/.gitignore`）。构建产物每次 `npm run build` 生成；
  冒烟脚本缺 dist 会直接退出码 2 并告诉你先 build，不会假装跑过。
- **依赖安装必须走国内镜像**：默认 registry 在本机实测 6 分钟没拉完一个包（无 node_modules 落地），
  换 `registry.npmmirror.com` 后 1 分 5 秒装完 133 包。命令写进 README 的复现须知。
- **首屏 920KB（gzip 288KB）是 antd**：已按 react/antd 拆包，业务代码 32KB；不为单机作品上路由级懒加载。
- **ECharts 走 CDN**（`reportHtml` 里写死的 jsdelivr）：离线时图表不渲染，表格仍在。要离线可用得把 echarts 打进 dist，
  属于后续可选优化，不在本票范围。
- **写接口无鉴权**：`write-enabled` 只是开关，不是权限。谁能访问端口谁就能改白名单 —— Ticket 14 补。

### 一处「报告判断偏严」，如实说明

报告写「`paid_order_cnt` 被 **3 个**指标引用（含 `pay_conversion_rate`）」。实测查下来是 **2 个**：
`pay_conversion_rate` 的 `table_name` 是 `ads_channel_conversion_di`，它 SQL 里的 `paid_order_cnt` 是**那张表**的同名列，
不是 `ads_trade_overview_di.paid_order_cnt`。守卫按 `table_name / denominator_table = 当前表` 过滤是对的 ——
否则「A 表删一个字段，因为 B 表有同名列的指标而被拦住」，守卫就变成了误报机器。

也就是说：**报告提的问题成立，但多算了一个引用方**。修完 400 文案里点名的是 `paid_order_cnt, pay_rate` 两个，符合预期。
