## 2. 三条债的实测证据

### 2.1 QA-14 P2-1：急停态冒烟从「异常退出」变回可用

修复前（QA-14 报告描述的现象）：`SMOKE_PORT=5176 node qa/smoke_frontend.cjs http://127.0.0.1:18098`（`write-enabled=false`）
在「指标页：非法口径被运维急停拒绝」之后，正向保存段无条件等「已保存…」，20 s 超时 → 整个脚本以「冒烟脚本异常」退出。

修复后：

| 实例 | 结果 |
|---|---|
| **18097**（默认 `write-enabled=true`） | **38/38**，含「指标页：编辑后保存走通（PUT /api/metrics 正向路径）」 |
| **18098**（`--datapilot.metadata.write-enabled=false`） | **32/32**，含「急停态编辑保存被 403 拦下」「急停态保存失败后弹窗保持打开」两条新断言 |

急停态的 32 项里，原「29/29」的 29 条全部在内 —— Ticket 14 落地记录里那条数据自本票起重新可复现
（中间 `9931743` 引入的失效窗口已关闭）。

### 2.2 QA-15 P3-1 / P3-3：恒真判据与阈值残留

① 段现在按库的实际情况走分支，实测输出：

```
[PASS] 库里有 max_complexity 行 → 阈值取行值 3（不覆盖运维手调）  3
```

缺行分支**端到端构造不出来**（`gate_config` 没有 DELETE 接口，`seed.sql` 对 `max_complexity` 是 `INSERT IGNORE`），
所以脚本里点明「由单测 `CostGateComplexityTest#defaultThresholdKeepsDimensionlessQuestionsPassing` 覆盖」，
不再用一条永远为真的 `or` 假装测过。

`finally` 兜底是**实跑验证**的，不是只看代码：把脚本副本在「阈值已改成 1 之后」插一行 `raise` 模拟中途崩溃，
输出 `[兜底恢复] 中途退出，max_complexity 1 → 3`，退出后查库确认为 `3`。

（先试过 `SIGINT` 打断：Windows 上 `Popen.send_signal(SIGINT)` 不作用于子进程，4 次都没打断成功、子进程照常跑完 17/17，
这条思路作废，改用注入异常。此处如实记录，避免下一个人重复踩。）

顺带修的第 0 段：原来探的是不存在的 `/api/metadata/health`，而 `call()` 把 `HTTPError` 吞成 `(code, body)`，
**404 也会继续往下跑** —— 那条「服务可达」从来没有真的校验过状态码。现在改真实路径并断言 200。

### 2.3 QA-16 P2-1：C5② 的「显式拒绝」落到代码

`qa/verify_scope_guard.py` 18/18：

| 问法 | 结果 |
|---|---|
| 近7天累计支付用户数是多少 | `REJECTED`，文案含「当天去重人数」「无法重算 `COUNT(DISTINCT user_id)`」「不会给一个偏大的数」，并给「每天的支付用户数」与「支付订单数 / 支付 GMV」两条替代问法；`sql=null rows=[]` |
| 本月付费用户数 / 近30天合计成交用户数 / 最近7天付费人数 | 同样被拦（别名来自 `metric_def.aliases`） |
| 10月19日的支付用户数 | 未被守卫拦（单日去重合法） |
| 近7天每天的支付用户数 / 每日…走势 / 按天趋势 | 未被守卫拦 |
| 支付用户数占总订单数的比例 | 未被守卫拦（「总」是分母修饰，不是跨期词） |
| 近7天累计支付订单数 / 当天总GMV | 未被拦；GMV 仍 `53042.41` |

一条必须说清的边界：放行的那几类问题在 **stub 模式下仍会落到「无法识别查询意图」**，因为它们不在 golden set 里，
stub 认不出来。**「没被守卫拦」≠「能答出来」** —— 守卫只是把「本来就答不了、还可能答错」的那一类提前挡掉并解释清楚，
剩下的交给召回/LLM/闸门。这条不影响本票结论，但看 18/18 时别误解成「这些题现在能答了」。
