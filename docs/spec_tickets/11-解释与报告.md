# Ticket 11：解释 + 报告

## 目标
ExplainStep（answer/chartType）+ ReportStep（reportHtml），响应含三字段，且报告与结果数据对齐。

## 背景
来自 A3（Spec §3 阶段③）。审计 P1#9：判据过松，「非空」<html> 也算非空，需收紧。

## 修改范围
- `agent/step`：ExplainStep/ReportStep
- AgentEngine 链尾

## 任务
1. ExplainStep 生成 answer + chartType（chartType 按结果形状判定：单值→metric、多行单列→bar、多行多列→table/line）
2. ReportStep 生成 reportHtml（ECharts HTML，series 长度 = rows 长度）

## 验收标准
响应含 answer/chartType/reportHtml 三字段；**reportHtml 含 echarts 且 series 长度 = rows 长度；chartType 按形状判定正确**。

## 测试要求
集成测试：打 /api/ask，断言三字段存在 + reportHtml 含 echarts + series 长度 = rows 长度 + chartType 符合形状。只测外部行为。

**为什么必须加 `status`（票面没写，是本票的连带影响）**

Ticket 01~10 的判据里有一个隐含约定：**`answer` 非空 = 这次没跑成功**。评测脚本
（`eval/run_eval.py`）和 e2e（`qa/e2e_stub.py`）都这么判。Ticket 11 之后 `answer` 在成功时
也有内容（「gmv_total = 53042.41」），于是 15 题**全被判成 `exec_failed`**（实测：准确率 0/15，
而 SQL 形状分仍 49/49 —— 数字自相矛盾，正是判据坏了而不是链路坏了）。

修法不是让解释节点「成功时别写 answer」（那就没有解释了），而是把判据换成显式字段：
`AskResponse.status`，两个脚本改为「有 status 按 status，没 status 回退旧口径」，
所以老响应的行为不变。

**票面偏差（1 条）**

1. **解释不调 LLM，是模板生成**。票面只说「生成 answer + chartType」，没说用不用模型。
   选择模板的理由：同一份 rows 让模型自由发挥，就有机会说出数据里没有的结论（幻觉最贵的一种），
   而模板只能说数据里有的东西。代价是句式单一（「共 3 行（channel_name → rate）：APP=0.1、…」）。

**已知边界**

- **ECharts 走 CDN**（`cdn.jsdelivr.net`）：无网时图表区空白，页面里的表格仍在 —— 把 1MB 的
  `echarts.min.js` 塞进每个响应体不现实，这是明确接受的降级路径。前端（Ticket 13）接上后
  会用自己的依赖，这份 HTML 主要给「导出/离线看」用。
- `chartType` 只有形状规则，没有语义：Q13「类目 + 金额」是 1 行 2 列 → `bar`，但单行柱状图
  的信息量不如 `metric`。规则与票面一致（多行多列才可能是 table/line），此处不改。

| 报告条目 | 根因 | 落地 |
|---|---|---|
| P2-2 失败响应仍报 `chartType=table` | `AgentContext.chartType` 的字段初值就是 `"table"`（Ticket 01 的占位），失败/拒绝时没人覆盖 ⇒ 前端按 chartType 渲染会拿到空图，而它该表达的是「没有图表」 | 初值改 **`null`**；`HitlController` 的「预览已过期」响应也不再用 `"table"` 占位。断言：`verify_explain.py`「拒绝时 chartType = null + reportHtml 为空」，实测 `10月12日`（数据范围外）→ `status=REJECTED, chartType=null` |
| P2-1 拒绝与失败没分开 | 同 QA-10 P2-3 | 一起在 Ticket 10 的 10b 补丁里改（`AgentContext.reject(reason, by)` + `RunStatus.of` 认 `rejectedBy`）。本票视角的验收：4 类明确拒绝（无上下文追问 / 同比 / 换维度 / 未命中）现在全部 `REJECTED` |
| P2-3 `verify_explain` 只覆盖 5 题、无环比组合 | 5 题都是 metric + bar，**line 分支（日期首列）没有集成样本**；且都不带 sessionId，最易回归的「已有 answer 不被覆盖」不在脚本里 | `CASES` 扩到 **15 题全量**（metric 5 / bar 9 / **line 1：Q14**），每题加一条「option 段内无裸 `<`」；新增两组：①带 sessionId 的环比轮次 → `answer` 保留「本期…；环比…」②明确拒绝 → `chartType=null`。脚本从 40 项涨到 **142 项全绿** |

**为什么不去凑一个 `table` 样本**：15 题里没有 3 列以上的结果。为了一种形状去编一条评测集外的查询，
会让评测集变成「为了覆盖代码而写的问题」而不是「用户真会问的问题」。`table` 仍只由
`ExplainStepTest.threeOrMoreColumnsIsTable` 覆盖 —— 这条取舍在票面「已知边界」里，报告也接受。
