## 一、项目概述

DataPilot 是一个两层架构的个人秋招项目：

- **平台层（当前主线）**：流批一体湖仓数据平台，核心链路 MySQL CDC→Kafka→Flink→Paimon(四层湖留存)+StarRocks(ADS 热查询)，可视化层 = Dinky（数据开发）+ DolphinScheduler（调度）+ go-view（大屏）+ Grafana（监控），安全层 = Ranger（权限）。
- **应用层（暂缓）**：Ontology 问数 Agent，Text2SQL + RAG，只连 StarRocks 只读账号。
- **两层唯一接口**：StarRocks 只读账号，数据方向平台→应用单向。

底座弃用 DataSophon（多机 Linux 集群管理平台，单机 Windows+Docker 跑不起来），改手工 Docker 编排。

## 二、架构总览（定稿）

```
MySQL(源库 cdc_source.orders, binlog)
        │  CDC (job1)
        ▼
      Kafka(ods_douyin_order_cdc)
        │  (job2)
        ▼
      Flink ──► Paimon 四层湖留存（HDFS /paimon_warehouse）
        │           ODS(ods_orders) → DWD(dwd_orders) → DWS×3 → ADS×4
        │                                          │ (job5 双写)
        │                                          ├─► Paimon ADS×4（湖冷存储）
        │                                          └─► StarRocks ADS×4（仓热查询）
        ▼
   StarRocks（内表，供查询）
        ▲
   Ontology 问数 Agent（只读账号 agent_ro）
```

**关键决策（用户拍板）**：StarRocks 不读 Paimon（版本交集为空：Flink 1.20 需 Paimon 1.0，StarRocks 3.3.8 内置 paimon-bundle 0.8.2 读不了 Paimon 1.x）。改为 Flink 把 ADS 直写 StarRocks 内表，Paimon 负责四层湖留存。

- **数据引擎层**：MySQL / Kafka / Flink / Paimon / StarRocks / ZooKeeper / Hadoop(HDFS+YARN) / Hive Metastore
- **可视化调度层**：Dinky（FlinkSQL 开发平台）/ DolphinScheduler（工作流调度）/ go-view（数据大屏）/ Grafana（监控）
- **安全层**：Ranger（统一权限管理）+ StarRocks 只读账号

## 五、关键踩坑记录（重要）

### 环境部署坑
1. **MSYS 路径转换破坏挂载**：Git Bash 用 `docker run -v /opt/...` 时路径被转成 `E:/...PortableGit/...`，导致 Flink 无 Paimon jar、StarRocks 数据没落盘、Hive 误连 Derby、网络分裂。**解法：全部改用 compose 文件声明挂载 + 统一 hadoop-net 网络**。
2. **Hive Metastore 重复初始化**：跳过 init 的变量是 `IS_RESUME=true`（不是 SKIP_SCHEMA_INIT）。
3. **StarRocks 挂载遮蔽**：只能挂持久化子目录 `fe/meta`、`be/storage`。
4. **Dinky 缺 MySQL 驱动**：官方包不含 JDBC 驱动，需手动放进 `extends/` 再建镜像。
5. **Ranger 登录 URL**：`POST /login`（Spring Security 5.7），非 `/j_spring_security_check`。
6. **Grafana 中文**：环境变量 `GF_USERS_DEFAULT_LANGUAGE=zh-Hans`（`default_language` 在 `[users]` 段）。
7. **daocloud 镜像限流**：大批量拉镜像要分批。

### 链路打通坑（核心）
8. **StarRocks Stream Load Connection refused（最关键）**：allin1 镜像 entrypoint 每次启动把 BE 注册成 `127.0.0.1`，connector 从 FE 拿 BE 地址后在 Flink 容器连自己失败，作业无限 RESTARTING。**解法：Flink StarRocks sink 的 `load-url` 用 feproxy 8080 端口**（allin1 内置 nginx，容器内跟随 FE 307 重定向到 BE），`jdbc-url` 仍用 9030。改 BE priority_networks 到 172.24 网段会破坏 FE/BE heartbeat，不可行。
9. **版本冲突（架构定稿根因）**：Flink 1.20 只支持 Paimon 1.0，StarRocks 3.3.8 内置 paimon-bundle 0.8.2 读不了 Paimon 1.x，交集为空。→ 让 StarRocks 不读 Paimon。
10. **Paimon 主键=分区字段冲突**：`Primary key constraint [dt] should not be same with partition fields`，去掉 PARTITIONED BY 或换主键。
11. **Dinky 不支持 EXECUTE STATEMENT SET**：自动合并多 INSERT。
12. **Dinky type 字段是执行模式（standalone/local）不是方言**：dialect 才是 FlinkSQL。
13. **Dinky submitTask 不取消旧作业**：重复提交产生重复 Flink job，编排脚本用「先查 RUNNING 再跳过」规避。
14. **Kafka Windows 挂载崩溃**：原子 rename 失败导致 storage offline，换全新目录 kafka-data + force-recreate。

### 调度编排坑
15. **DolphinScheduler API 用 form 参数（@RequestParam）不是 JSON body**：登录/建项目/建工作流都要 form-urlencoded + urlencode，传 JSON body 报 `Required request parameter 'xxx' is not present`。
16. **taskDefinitionJson 缺 isCache 字段 → NPE**：`transformTask` 里 `getIsCache().getCode()` NPE，补 `"isCache":"NO"`。
17. **taskRelationJson 首个关系 preTaskCode=0 时 preTaskVersion 必须=0**。
