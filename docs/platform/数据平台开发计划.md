## 二、P0 主链路（已完成 ✅，全流版）

1. ✅ MySQL 建 cdc_source：orders 事实表（只存外键）+ dim_product/dim_channel/dim_province 维度表 + 造 75 条订单
2. ✅ Kafka 建 ods_douyin_order_cdc（3 分区）+ ods_dim_*_cdc（维度表）
3. ✅ job1 MySQL CDC → Kafka（4 表一表一 topic，sink 按主键 hash 分区）
4. ✅ job2 Kafka → Paimon ODS + DIM（湖）
5. ✅ job3 ODS → DWD（湖，事实表只存外键）
6. ✅ job4 DWD → DWS×4（湖，lookup join 拼维度 + trade_overview 流式维护 + State TTL 7d + checkpoint 60s）
7. ✅ job5 DWS → StarRocks×4（流作业，读 DWS changelog 直写 SR 主键表 upsert）
8. ✅ job6 DWS → StarRocks×4（批作业，从 DWS 全量重建 SR 的补数/回刷入口）

**关键卡点已解决**：
- StarRocks allin1 的 BE 注册为 127.0.0.1 导致 connector Stream Load 连错，用官方 feproxy 8080 端口方案解决（load-url 用 `sr-ai-analysis:8080`）。
- 中文双重编码：`docker exec -i mysql < file` 默认 latin1 解读 stdin，须加 `--default-character-set=utf8mb4`。
- Flink lookup join：Paimon 表无隐式 proc_time，须子查询包装 `(SELECT *, PROCTIME() AS proc_time FROM dwd_orders)`。
