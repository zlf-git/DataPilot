## 1. 项目背景与立项动机

传统业务取数依赖数据开发工程师手工编写 SQL：需求方提数 → 数开翻译口径 → 写 SQL → 出结果，链路长、口径不统一、沟通成本高。

大模型让 Text2SQL 成为可能，但**裸调 LLM 生成 SQL 不可控**——存在三类风险：

1. **幻觉**：LLM 编造不存在的表名、字段名。
2. **越权**：生成的 SQL 可能包含写操作、删库、注入。
3. **口径错**：同一个"销售额"，不同人理解不同（含不含退款、含不含税），LLM 无法凭空知道。

**立项目标**：做一个"口径可控、安全只读、引擎可插拔"的轻量智能问数 Agent，让自然语言取数既快又准又安全。

**演进动机（从 RAG 到 Agent）**：

第一版用 Dify 搭了「RAG + Text2SQL」固定工作流，存在两个局限：

1. **流程写死**：节点和顺序人工编排，无法应对"口径不清需二次查指标""SQL 报错需重写"等动态场景。
2. **只检索不决策**：RAG 解决"答得准"（检索到对的 schema），但不解决"干得完"（拆解任务、调用工具、失败重试）。

因此本项目从「检索增强」升级为「任务自治」：让 LLM 自主决定调用哪些工具、下一步做什么、失败自动重试，把方向盘的主动权交给模型。

---

## 2. 项目目标

- **一句话目标**：用户用自然语言提问，系统召回元数据 → 生成 SQL → 校验 → 执行 → 返回人话解释 + 数据。
- **本质目标**：核心不是"能生成 SQL"，而是"生成的 SQL 安全、口径正确、可追溯"。

## 4. 功能需求

### 4.0 对标 DataAgent 的功能取舍

本项目借鉴 Spring AI Alibaba DataAgent（企业级智能数据分析师），对其 8 大特性做如下取舍（5 天最小版）：

| DataAgent 特性 | DataPilot 做法 | 决策 |
|---|---|---|
| 智能数据分析（Text2SQL + 多轮） | 7 步链路 + 多轮对话 | ✅ 借鉴实现 |
| RAG 检索增强（向量库语义检索） | 关键词 + SQL 模糊匹配（不引向量库） | 🟡 简化 |
| 智能报告生成（ECharts HTML/MD） | 生成含 ECharts 的 HTML/Markdown 报告 | ✅ 借鉴实现 |
| Python 深度分析（容器沙盒） | 不做，用「结果解释」替代 | ❌ 砍 |
| 人工反馈（Human-in-the-loop） | 极简：SQL 生成后允许确认/修改 | 🟡 简化 |
| 多模型调度（模型注册表） | 配置项切换 LLM（DeepSeek/Qwen） | 🟡 简化 |
| MCP 服务器 | 不做 | ❌ 砍 |
| API Key 管理 | 不做 | ❌ 砍 |

**借鉴重点**：Text2SQL 编排思想 + 知识三层 + 报告生成；**砍掉**：需 Docker 沙盒 / 企业级权限的重特性。

### 4.1 自然语言问数（P0）
用户输入自然语言问题，系统返回结论解释 + 结构化数据。

### 4.2 多节点 Agent 编排（P0）
采用 7 步链路（借鉴 Spring AI Alibaba DataAgent 的 StateGraph 多节点编排思想，手写状态机实现）：

```
用户提问
 → ① 问题改写（LLM）
 → ② 表路由 / 元数据召回（关键词 + 语义）
 → ③ Prompt 组装（表 DDL + 字段注释 + 枚举 + 口径 + few-shot）
 → ④ SQL 生成（LLM）
 → ⑤ SQL 校验（白名单 + 只读 + LIMIT + 语法）
 → ⑥ SQL 执行（MySQL / StarRocks）
 → ⑦ 结果解释（LLM 转人话）
```

### 4.3 语义模型 / 元数据管理（P0）
对齐 DataAgent 的「知识三层」，维护 5 张元数据表，支撑召回与口径统一：

| 知识层 | DataAgent 概念 | DataPilot 表 | 作用 |
|---|---|---|---|
| 语义模型 | 表 / 字段 / 关系 | `semantic_model` + `field_metadata` | 可查询的表、字段、枚举值 |
| 业务知识 | 术语 / 口径 | `metric_def` + `term_dict` | 指标口径（只定义一次）、业务黑话同义词 |
| 智能体知识 | few-shot 示例 | `few_shot_example`（新增） | 问题-SQL 示例对，提升生成准确率 |

### 4.4 SQL 安全校验（P0）
- 只读白名单：仅允许 SELECT。
- 拒绝写操作（INSERT/UPDATE/DELETE/DDL）。
- 强制 LIMIT，防止全表拖垮。
- 表名白名单校验（只能查元数据登记过的表）。

### 4.5 结果解释（P0）
把 SQL 结果翻译成人话结论，而非只返回原始表格。

### 4.6 可插拔 SQL 引擎（P1）
定义统一 `SqlExecutor` 接口，支持 MySQL 与 StarRocks 两种实现，切换引擎只改配置不改代码。

### 4.7 多轮对话（P1）
携带会话历史，支持追问（如"那环比呢"）。

### 4.8 前端（P1）
极简 HTML 聊天框：输入问题，展示结论 + 数据。

### 4.9 智能报告生成（P1，借鉴 DataAgent）
分析结果汇总为含 ECharts 图表的 HTML/Markdown 报告，所见即所得（柱状图 / 折线 / 饼图 / 表格）。

### 4.10 多模型切换（P2，借鉴 DataAgent 轻量版）
通过配置项切换 LLM（DeepSeek / Qwen），不引模型注册表，够用即可。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | SQL 只读、防注入、表白名单 |
| 性能 | 单次问数响应可接受（不含 LLM 时间，SQL 执行秒级） |
| 可维护性 | 元数据与业务数据分离，节点职责单一 |
| 可扩展性 | 新增引擎/新增节点不改主链路 |

## 6. 范围边界（做什么 / 不做什么）

**首版（5 天）做（对标 DataAgent）：**
- Text2SQL 7 步链路 + 多轮对话（借鉴「智能数据分析」）
- 知识三层：语义模型 + 业务知识 + 智能体知识（借鉴「知识配置」）
- 智能报告生成：ECharts HTML/Markdown（借鉴「智能报告」）
- 轻量 RAG：关键词 + SQL 匹配（不引向量库）
- 多模型配置切换、可插拔数据源、单机部署

**首版不做（后续可加）：**
- Python 沙盒深度分析（需 Docker）、MCP 服务器、Human-in-the-loop 完整版、API Key 管理、多租户、完整权限体系、Nuxt 前端、向量数据库。

---

## 7. 验收标准

1. 提问"上月销售额是多少"，能返回正确数字 + 人话解释。
2. 输入含写操作/注入的恶意问题，SQL 被拦截，不执行。
3. 切换 StarRocks 引擎，只需改配置即可跑通同一条链路。
4. 追问"那环比呢"，能基于上下文正确回答。
