> 执行模块的职责：把通过前三道闸门校验的 IR 转成**受控 SQL**，用 StarRocks 只读账号执行，返回结构化结果。关键点在于——**LLM 不再直吐 SQL，而是吐 IR，因此我方代码做 IR→SQL 时可以用参数化绑定，从根上消除注入风险**。

---

## 1. 执行链路

```
IR（已过 存在性/权限/代价 闸门）
  → IR→SQL 转换（SqlGenerator，参数化绑定）
  → 语法闸门（JSqlParser 校验 + 白名单二次比对）
  → 执行（StarRocks agent_ro 只读账号 + PreparedStatement）
  → 结果自检
  → 返回
```

---

## 2. 核心红利：参数化绑定复活

传统 Text2SQL 与 IR 架构的关键差异：

| 方案 | LLM 产出 | 能否参数化 | 注入风险 |
|---|---|---|---|
| 裸 Text2SQL | SQL 字符串 | 不能（字符串拼接） | 高，靠白名单/只读账号兜底 |
| IR 架构 | 结构化 IR | **能**（我方代码生成 SQL，value 走 `?` 占位） | 从根消除 |

**结论**：IR 架构让「参数化绑定」重新可行，值级安全从「白名单 + 闸门 + 只读账号」三层，升级为「**参数化绑定 + 白名单 + 闸门 + 只读账号**」四层。这是 IR 相比裸 Text2SQL 的又一层安全红利。

## 3. IR → SQL 转换规则

### 3.1 生成规则

| SQL 子句 | 来源 | 规则 |
|---|---|---|
| SELECT | `metrics` + `dimensions` | 每个 metric 取 `metric_sql`（口径），每个 dimension 取 `field` |
| FROM | metric/维度涉及的 `table` | 单表直接引用；多表按 `dt` 链式 join |
| WHERE | `filters` | `field op ?`，value 进参数列表（**不拼字符串**） |
| GROUP BY | 有聚合指标时 | 按所有 `dimensions.field` 分组 |
| ORDER BY | `orderBy` | `field direction` |
| LIMIT | `limit` | 直接透传（已被代价闸门封顶） |

### 3.2 聚合判定

- 指标 `metric_sql` 含 `SUM/AVG/COUNT/MAX/MIN` → 聚合指标，需要 `GROUP BY dimensions`。
- `metric_type=composite` → 输出 `ROUND(分子 / NULLIF(分母, 0), 4) AS <metricId>`，列别名取 **metricId**（不是 `ratio`），Q6/Q9/Q15 三个复合指标列名规则统一。
- 跨表分母（填了 `denominator_table`）→ 生成标量子查询，**不生成 JOIN**：JOIN 在一对多时会放大行数，占比就错了。
- ADS 表里已有的预计算列（`pay_conversion_rate`、`order_conversion_rate` 等）**不作为指标口径**，一切以 `metric_def.metric_sql` 为准（Ticket 05 已把 `pay_conversion_rate` 落成 composite）。

### 3.3 指标口径写法（写入端契约，QA-05 P2-3）

`PUT /api/metrics` 只接受下表三种写法，其它一律 400 —— 写入口是严格的一侧，生成器读取端是宽容的一侧，两者不互为契约。

| 类型 | 写法 | 例 |
|---|---|---|
| 单聚合（`simple`/`uv`） | `FN(field)` 或 `COUNT(*)`，**不带外括号** | `SUM(total_gmv)` |
| 同表比值（`composite`） | `FN(a)/FN(b)`，两侧都是单聚合，**不带外括号** | `SUM(paid_order_cnt)/SUM(visit_uv)` |
| 跨表占比（`composite` + `denominator_*`） | `metric_sql` 只写分子单聚合；分母写 `denominator_table` + `denominator_sql`（本身必须是单聚合） | `SUM(gmv)` + `ads_trade_overview_di` + `SUM(total_gmv)` |

- 允许函数名与括号间空格、括号内空格（`SUM ( total_gmv )`、`SUM(a) / SUM(b)`）。
- **禁止外括号**：`(SUM(a))/(SUM(b))` 写入被 400 拒绝（`MetadataService.RATIO_PATTERN`）。生成器 `IrToSqlConverter.braces()` 对多一层括号做了兼容，那是为了兜住手工改库/历史迁移的数据，**不是可用写法**。
- 跨表占比的分母 SQL 必须自带聚合，否则标量子查询返回多行、执行期直接报错。

## 4. 关键类设计

```java
// 转换器：IR → 受控 SQL
public class IrToSqlConverter {
    private final MetadataRepository metadata;   // 读 metric_def 拿 metric_sql

    public SqlCommand convert(QueryIr ir) {
        // SELECT：metric_sql + dimension.field
        // FROM/JOIN：多表按 dt 链式 join
        // WHERE：filters → "field op ?"，value 进 params
        // GROUP BY：有聚合指标时按 dimensions 分组
        // ORDER BY / LIMIT
        return new SqlCommand(sql, params);
    }
}

// 产物：SQL + 绑定参数（value 永不拼进 SQL 字符串）
public record SqlCommand(String sql, List<Object> params) {}

// 执行器接口（Ticket 07 接口化）：切换引擎只换实现，主链路与五道闸门零改动
public interface SqlExecutor {
    String engineName();                          // starrocks / mysql
    List<TableMeta> listTables();                 // information_schema
    List<Map<String, Object>> query(String sql);  // 仅自检/运维用
    List<Map<String, Object>> query(SqlCommand cmd); // 主链路唯一入口：? 参数化
    default Set<String> readableTables() { return Set.of(); } // 白名单钩子
}

// 两个引擎共用执行逻辑（都是 MySQL 协议），子类只给 engineName + 声明表
public abstract class JdbcSqlExecutor implements SqlExecutor { /* query/query(listTables) 实现在此 */ }
public class StarRocksSqlExecutor extends JdbcSqlExecutor { /* @ConditionalOnProperty(type=starrocks) */ }
public class MysqlSqlExecutor     extends JdbcSqlExecutor { /* @ConditionalOnProperty(type=mysql)     */ }
```

## 5. 完整示例

### 示例一（Q6：单表 + 预计算指标）

IR：
```json
{
  "metrics": [ { "metricId": "支付转化率", "table": "ads_channel_conversion_di" } ],
  "dimensions": [ { "field": "channel_name", "table": "ads_channel_conversion_di" } ],
  "filters": [ { "field": "dt", "table": "ads_channel_conversion_di", "op": "=", "value": "2026-10-19" } ],
  "orderBy": [ { "field": "pay_conversion_rate", "direction": "DESC" } ]
}
```

生成 SQL（参数化）：
```sql
SELECT channel_name, pay_conversion_rate
FROM ads_channel_conversion_di
WHERE dt = ?
ORDER BY pay_conversion_rate DESC
```
参数：`["2026-10-19"]`

### 示例二（Q11：单表 + 聚合指标 + GROUP BY）

IR 指标为「GMV（渠道/地域）」→ `metric_sql = SUM(gmv)`，维度为 `channel_name`。

生成 SQL：
```sql
SELECT channel_name, SUM(gmv) AS gmv
FROM ads_channel_conversion_di
GROUP BY channel_name
ORDER BY gmv DESC
LIMIT ?
```
参数：`[1]`（对应 `LIMIT 1`）

### 示例三（Q15：多表 join）

两表按 `dt` 链式 join：

```sql
SELECT c.gmv, t.total_gmv, c.channel_name
FROM ads_channel_conversion_di c
JOIN ads_trade_overview_di t ON c.dt = t.dt
WHERE c.dt = ? AND t.dt = ?
```
参数：`["2026-10-19", "2026-10-19"]`

> 占比这类复合指标，demo 阶段在 IR 层表达为「两个 metric + 服务端算比值」，或后续在 `metric_def` 里支持复合口径 SQL，此处不展开。

## 6. 与闸门的衔接

| 环节 | 闸门 |
|---|---|
| IR→SQL 前 | 存在性、权限、代价已在 IR 层校验 |
| SQL 生成后 | 语法闸门：JSqlParser 解析 + 表/字段二次比对 |
| 执行 | StarRocks 用只读账号 `agent_ro`（权限闸门第二道）；MySQL 演示账号是 root，只靠应用层白名单 + 连接 `readOnly` |
| 结果 | 结果自检：空结果/异常值包装 |

## 7. 数据源配置（可插拔双引擎，Ticket 07）

```yaml
datapilot:
  engine:
    type: starrocks                                   # starrocks（默认）/ mysql
    url: jdbc:mysql://localhost:9030/mall_dw?...      # 换引擎只改这三行
    username: agent_ro
    password: AgentRo@2026
```

| 引擎 | 装配条件 | url 示例 | 账号口径 |
|---|---|---|---|
| `starrocks` | `type=starrocks`（缺省也生效） | `jdbc:mysql://localhost:9030/mall_dw` | **`agent_ro` 只读**，仅 SELECT，生产承诺 |
| `mysql` | `type=mysql` | `jdbc:mysql://localhost:3307/data_agent` | `root/root123` **读写演示账号**，仅本地演示，**不承诺只读**（票面「不包含」） |

- `type` 写错（如 `mysqll`）或 `url` 为空 → **启动即失败**，不会留下「两个执行器都没装配、跑到执行步骤才报 NoSuchBean」的隐式坑。
- 元数据库（语义层 `metric_def` 等）走 MySQL，与业务数据引擎分离；`EngineJdbc` 刻意<b>不</b>声明成 `DataSource` 类型，否则 Boot 的 `DataSourceAutoConfiguration` 会整体退让。
- 切完自查：`GET /api/health/engine` 返回 `engine` / `declaredTables`（引擎声明）/ `metadataTables`（`semantic_model`）/ `effectiveTables`（交集）/ 双向失配 / `consistent`。
- **切 MySQL 后时间窗口会显式拒绝**：演示库 `orders` 没有 `dt` 字段，「近 N 天」拿不到锚点 → 返回「表 orders 读不到时间字段 dt…」，DB 原文只进日志（Ticket 07 修复）。不带时间条件的单表问题照常跑通。
