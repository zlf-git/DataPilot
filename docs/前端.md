> F-07 定义前端页面与接口契约。核心设计：问数页**透明展示整条链路**（IR → SQL → 闸门状态 → 结果），不搞黑盒，演示时能把「语义层约束 + 五道闸门」看得一清二楚。

---

## 1. 页面清单

| 页面 | 角色 | 功能 |
|---|---|---|
| 问数页 `/ask` | 所有人 | 自然语言问数 + 链路透明展示 |
| 指标管理页 `/metrics` | 业务 | `metric_def` 自助 CRUD |
| 闸门配置页 `/gate-config` | 管理员 | `gate_config` 阈值调整 |
| 元数据页 `/metadata`（可选） | 管理员 | 表/字段白名单维护 |

---

## 2. 问数页（核心）

### 2.1 交互流程

```
输入问题 → POST /api/ask → 后端跑完整链路
  → 返回 { question, ir, sql, rows, gates[], costMs }
  → 前端分区展示
```

### 2.2 展示分区（透明化亮点）

| 分区 | 展示内容 | 作用 |
|---|---|---|
| ① 问题 | 原始问题 | 对齐上下文 |
| ② IR | 生成的 IR JSON（可折叠） | 展示「结构化中间态」，不是裸 SQL |
| ③ SQL | 由 IR 转出的受控 SQL | 展示参数化绑定后的最终 SQL |
| ④ 闸门 | 五道闸门逐条状态（通过 ✅ / 拦截 ⛔ + 原因） | 展示安全链路 |
| ⑤ 结果 | 结果表格 / 无数据提示 / 告警 | 最终答案 |

### 2.3 示例（评测集 Q6）

用户输入「10月19日各渠道的支付转化率分别是多少？按从高到低排序」后，页面展示：

- **IR**：`{ metrics:[{metricId:"支付转化率"}], dimensions:[{field:"channel_name"}], filters:[{field:"dt",op:"=",value:"2026-10-19"}], orderBy:[...] }`
- **SQL**：`SELECT channel_name, ROUND(SUM(paid_order_cnt) / NULLIF(SUM(visit_uv), 0), 4) AS pay_conversion_rate FROM ads_channel_conversion_di WHERE dt = ? GROUP BY channel_name ORDER BY pay_conversion_rate DESC, channel_name ASC`
- **闸门**：存在性 ✅ / 权限 ✅ / 代价 ✅ / 语法 ✅ / 结果自检 ✅
- **结果**：表格三行（APP 0.1000 / 小程序 0.1000 / 网页 0.0750）

## 3. 指标管理页（业务自助）

- 列表：展示 `metric_def` 全部指标（名称、口径 SQL、归属部门、负责人、状态）。
- 新增/编辑：业务填指标名、同义词、口径 SQL、归属部门、可用维度。
- 规则：同 `metric_name` 只允许一个启用中（同词唯一），新增同名词需停用旧定义。
- 无删除硬删，只停用（`status` 置停用），保留审计。

---

## 4. 闸门配置页（管理员）

- 展示 `gate_config` 当前值：`max_join` / `max_metric` / `max_limit` / `max_rows`。
- 调整阈值：`join≤2→3`、`limit≤1000→5000` 等。
- 记录修改人 `updated_by` + 修改时间。
- 业务用户无入口，进入即 403。

## 5. REST API 契约（v1.1，按实际实现对账）

> v1.0 写的 `PUT /api/metrics/{id}`、`PUT /api/gate-config/{key}` 是设计稿口径，实现里没有路径参数：
> 主键放在请求体里（`metric_id` / `param_key`），写接口统一是 `PUT` 到集合路径。
> Ticket 13 做前端时按实现对接，这里同步改成实际契约 —— **文档跟代码对不上时以代码为准，然后把文档改对**。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/ask` | 问数，一步到底 | 所有人 |
| POST | `/api/ask/preview` | 只校验不执行，返回 `previewId`（Ticket 12） | 所有人 |
| POST | `/api/ask/execute` | `{previewId, ir?}` 确认执行，重跑闸门①~④ | 所有人 |
| GET | `/api/metrics` | 指标列表 | 所有人 |
| PUT | `/api/metrics` | 新增/编辑指标（body 带 `metricId`） | 需 `write-enabled` |
| GET | `/api/gate-config` | 闸门阈值 | 所有人 |
| PUT | `/api/gate-config` | 调阈值（body 带 `paramKey`） | 需 `write-enabled` |
| GET | `/api/metadata/tables` | 表清单（`semantic_model`） | 所有人 |
| GET | `/api/metadata/fields` | 字段白名单 | 所有人 |
| PUT | `/api/metadata/fields` | 字段白名单 upsert（Ticket 13） | 需 `write-enabled` |
| DELETE | `/api/metadata/fields?tableName=&fieldName=` | 移出白名单（被维度/指标引用时 400） | 需 `write-enabled` |
| GET | `/api/health/{metadata,engine,llm,traces,session,hitl}` | 各模块自检 | 所有人 |
| GET | `/api/traces?limit=&sessionId=`、`/api/traces/{traceId}` | 运行列表 / 单次链路明细 | 所有人（Ticket 14 后收紧） |

`/api/health/metadata` 额外返回 `writeEnabled`：前端据此决定「编辑按钮能不能点」，
不让人点了保存才吃一个 403。

## 7. 与 Agent 的关系

- 问数页是 Agent 的**唯一对外入口**，后端只认 IR、只走只读账号，前端拿不到 SQL 拼写能力。
- 指标管理页 = 业务自助定义口径（F-01 指标层落地）。
- 闸门配置页 = 管理员调安全阈值（F-04 v1.1 落地）。

## 9. 写入凭证（Ticket 14）

后端只保护写接口，`/api/ask`、所有 `GET`、`/api/traces` 仍然匿名。写接口需要 HTTP Basic 凭证：

| 账号 | 角色 | 能写 |
|---|---|---|
| `admin` / `Admin@2026` | ADMIN | 指标口径、闸门阈值、字段白名单 |
| `dba` / `Dba@2026` | DBA | 仅字段白名单 |
| `business` / `Biz@2026` | BUSINESS | 什么都不行（用于验证「403 不是 401」） |

页面上的用法：页头右上角「写入凭证」→ 填用户名密码 → 之后所有请求自动带 `Authorization`。
凭证存 `sessionStorage`（base64，不是加密），关标签页即失效。任何写请求返回 401 时会自动弹这个框。

状态码怎么读：

- **401**：没带凭证或凭证错 → 补凭证（页面会自动弹框）
- **403 + 「权限不足」**：有身份但角色不够 → 换账号（弹框没用）
- **403 + 「写入已被运维急停」**：`datapilot.metadata.write-enabled=false` → 这是运维开关，换账号也没用

`GET /api/health/metadata` 返回的 `writeEnabled` 现在表达的是「急停是否解除」，不是「有没有权限」——
页面顶栏据此显示「写入可用 / 写入急停中」，与身份 Tag 是两件事。
